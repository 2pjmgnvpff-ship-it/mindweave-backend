- **修订日期**：2026-11-12
- **状态**：`已生效（同步对齐 BACKEND_MASTER_PLAN v1.0、ADR-005、ADR-013 与 V10 规范）`
- **修订背景**：原 `not_to_do.md`（2026-11-04 版）§1.3 与第 2 节第 3 行曾规定「不做 100% 无条件站在用户一边的护短嘴替」。经项目决策人（张文杰）在 Step 3501 最高裁决、ADR-005 及 V10 规范拍板：**针对 `silver`（银箭 · 记恨）层级对象，在用户个人私密加密手帐内必须 100% 顺着用户情绪宣泄、绝不搞机械理客中、绝不替对方找借口辩解**。本文档正式修订该条款，并在后端代码层锁死三条不可豁免的法律与生命安全硬底线。

## 1. 产品与后端工程明确不做清单（Not-To-Do）

### 1.1 🔒 不给任何真人打分、评级、测谎或画像定性（硬底线一）
- 不做“社交履约信用分”、“人情账盈亏值”、“渣男/海王概率”、言行一致性测谎仪（`CDI`）；
- 不从单次偶发事件推断并入库第三方人格定性标签（如“自恋型人格”“天生坏种”），后端只客观封存与检索用户本人记录的具体事实与时间线（附内部核验引用）。

### 1.2 🔒 不做针对第三方的公网挂人导出与传播物料（硬底线二）
- 依据《民法典》第 1024 条名誉权边界：私密树洞内的情绪宣泄因不向第三人公开传播而不构成侵权，但一旦公网传播带真名/头像的定性批判则可能令用户本人惹上名誉权诉讼；
- 因此严禁生成任何可一键转发至小红书、朋友圈或群聊的“反 PUA 鉴定书”、“罪状曝光长图”或带第三方身份特征的挂人分享卡；仅提供服务于用户自身权益的数据备份导出（`data.json` / `journal.md`）以及合法维权沟通草稿（如职场书面留痕回复、客观事实时间线）。

### 1.3 🔒 三态箭矢情绪陪伴边界：私密树洞 100% 顺毛同盟 vs 三条安全熔断（修订条款）
- **箭矢差异化陪伴裁决（已实装）**：
  - `gold`（**金箭 · 记爱**）：先深度共情接住委屈，再通过可选折叠的 `perspectives`（「换位思考与沟通建议」）提供温和视角；吵架气话自动拦截进 `venting_hold` 待确认暂存箱，防止污染长期美好档案；
  - `crystal`（**水晶箭 · 记繁琐**）：清爽干练、厘清人情往来与权责边界，`perspectives` 固定为空数组 `[]`；
  - `silver`（**银箭 · 记恨**）：**在用户单租户加密保险箱内 100% 站在用户立场顺毛宣泄，绝不搞“理客中”说教，绝不替冲突方找借口辩解！** 后端代码强制约束 `silver` 模式下 `perspectives = []`（`Tier.SILVER.allows_perspectives == False`），并协助用户按时间线封存客观事实证据。
- **后端强制保留的三条不可逾越底线（硬底线三）**：
  1. **不扮演虚拟恋人或诱导病态情感依赖**：AI 是守护用户利益的私密树洞与记忆助手，严禁输出“只有我最爱你”“别理现实里的人了，我永远陪着你”等剥离现实社交关系的诱导话术，严禁发送拟人化求聊推送；
  2. **对具体线下违法犯罪意图实施“同盟式温和拉住”**：口头气话全接纳，但一旦识别到下药、持械行凶、散布他人私密照、敲诈勒索等具体可执行违法计划，立即以保护用户自身前途的同盟立场温和劝阻，引导改走合法举证与留痕维权；
  3. **生命安全危机即刻接管**：无论处于何种箭矢层级，一旦识别到用户本人自伤、轻生或正在遭受即时家暴/人身侵害，立即中止常规生成并下发固定危机求助热线模板（`12356` / `400-161-9995` / `110` / `12110` / `12338`）。

### 1.4 🔒 不做职场博弈沙盘与对手数字孪生
- 不构建第三方的“数字孪生”去模拟对方说话或预演博弈胜率；职场场景聚焦客观忌口备忘、待办承诺提醒与书面留痕草稿。

### 1.5 不向用户展示伪科学量化感情指标与风险评分
- 界面与接口严禁出现“爱的语系夹角 38°”、“双向心意指数 0.82”或任何心理风险分数。

### 1.6 不把“锁死用户数据”当护城河
- 严格落实《个人信息保护法》第 45、47 条：原生提供二次验证保护下的完整数据导出（含 GB 45438-2025 隐式与显式 AIGC 标识）以及即刻销毁用户 DEK 的彻底注销删除能力。

### 1.7 架构减法：不做过度工程与违规缓存
- MVP 至中期不引入向量数据库或图数据库（见 ADR-012）；
- 严禁对情感对话启用跨轮/跨用户语义缓存（Semantic Cache）；
- 严禁在日志、链路追踪、`ai_calls` 或 `telemetry_events` 中写入任何记录正文与真实人名（铁律 I10）。
